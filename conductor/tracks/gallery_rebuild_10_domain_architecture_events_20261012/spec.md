# Specification: Domain Component Architecture, Event Decoupling & Shell Mediator (`gallery_rebuild_10_domain_architecture_events_20261012`)

## Overview
Establish a clean **Mediator (Smart Shell, Self-Contained Widgets)** architecture across the built-in Component Gallery domain collection (`theme_select`, `search_box`, `sandbox_params`, `nav_tree`, `sandbox_toolbar`, `canvas_widget`). 

Domain components are legitimately domain-aware—they understand component trees, canvas viewports, and sandbox parameters. However, their current client-side scripts suffer from severe architectural overreach: leaf widgets act as autonomous application controllers that write cookies, hijack `window.location.href`, penetrate preview iframe DOMs, and attach un-scoped document-level listeners.

This track decouples all global browser side-effects (cookies, web storage, URL query routing, global keyboard shortcuts, and iframe synchronisation) into the host application coordinator ([`<dds-gallery-shell>`](file:///home/marcel/projects/dj-design-system/dj_design_system/static/dj_design_system/gallery-shell.ts)), leaving domain components as self-contained, event-driven widgets that communicate exclusively via inputs, slots, and standard bubbling `CustomEvent`s.

---

## Architectural Principles: The Mediator Pattern

```
┌────────────────────────────────────────────────────────────────────────┐
│                        <dds-gallery-shell>                             │
│  Owns: document.cookie, localStorage, URL routing/history,             │
│        sessionStorage, global keydown ('/'), iframe postMessage        │
└────────┬──────────────────────┬──────────────────────┬─────────────────┘
         │                      │                      │
         │ (Events & Attrs)     │ (Events & Attrs)     │ (Events & Attrs)
         ▼                      ▼                      ▼
┌──────────────────┐  ┌──────────────────┐  ┌───────────────────────────┐
│ <dds-theme-select│  │ <dds-search-box> │  │   <dds-sandbox-toolbar>   │
│ Leaf UI widget;  │  │ Leaf UI widget;  │  │   Leaf UI widget;         │
│ dispatches       │  │ dispatches       │  │   dispatches              │
│ dds:theme-change │  │ dds:search-select│  │   dds:sandbox-control     │
└──────────────────┘  └──────────────────┘  └───────────────────────────┘
```

1. **Domain Semantics Allowed:** Domain components may accept domain-level data structures (`ThemeOption`, `NavTreeNode`, `SearchIndexEntry`) and use domain terminology.
2. **Zero Global Side-Effects in Leaf Widgets:** Leaf custom elements must never mutate `document.cookie`, `window.localStorage`, `window.sessionStorage`, or `window.location.href`.
3. **Outward Communication via Events:** State transitions are communicated upwards solely through standard, bubbling `dds:*` `CustomEvent`s with typed details.
4. **Shell as Central Coordinator:** `<dds-gallery-shell>` intercepts bubbling domain events and coordinates persistence, URL updates, and iframe synchronisation in one single place.

## Detailed Functional & Architectural Requirements

### 1. Theme Selection & Storage Decoupling (`theme_select`)
- **Remove Cookie & LocalStorage Mutation from Leaf Component:**
  - Strip `document.cookie` and `window.localStorage.setItem('dds_theme', ...)` from [`DDSThemeSelectElement`](file:///home/marcel/projects/dj-design-system/dj_design_system/components/gallery/domain/theme_select/theme_select.ts#L60-L68).
  - Component solely dispatches `new CustomEvent('dds:theme-change', { bubbles: true, detail: { theme } })`.
- **Centralise Theme Persistence in `DDSGalleryShellElement`:**
  - Enhance [`gallery-shell.ts`](file:///home/marcel/projects/dj-design-system/dj_design_system/static/dj_design_system/gallery-shell.ts#L174-L222) to write `document.cookie = 'dds_theme=' + theme + '; path=/; SameSite=Lax'` and update `localStorage` whenever `dds:theme-change` is handled.
  - The shell remains the single source of truth for URL synchronisation (`_dds_theme`), input updating, and iframe `src` rewriting.
- **Typed `ThemeOption` Dataclass:**
  - Export a co-located `@dataclasses.dataclass(frozen=True) class ThemeOption:` (`value: str`, `label: str`, `icon: str = "sun"`) from `theme_select.py` and `__init__.py`.
  - Remove borrowed imports of toolbar models and duck-typed dictionary parsing.

### 2. Sandbox Toolbar & URL Navigation Decoupling (`sandbox_toolbar`)
- **Eliminate URL Hijacking in `sandbox_toolbar.ts`:**
  - Remove `window.location.href = ...` mutations, query parameter parsing, and `#pane-sandbox` hash evaluations from [`sandbox_toolbar.ts`](file:///home/marcel/projects/dj-design-system/dj_design_system/components/gallery/domain/sandbox_toolbar/sandbox_toolbar.ts#L112-L126).
  - Emit a bubbling `dds:sandbox-variant` `CustomEvent` with `{ variant: value }`, or allow anchor-based options (`href`) generated by Django view helpers to navigate natively.
- **Eliminate Child Component Boundary Piercing:**
  - Remove queries into child `dds-popout` DOM internals (`[data-popout-trigger] > span`, `[data-value]`).
  - Rely on the child component's public event contract (`dds:popout-select`) to update local button labels.
- **Scoped State & Co-located Option Dataclass:**
  - Remove hardcoded global `sessionStorage` key (`'dds_toolbar_state'`) from leaf components; delegate toolbar persistence to `<dds-gallery-shell>`.
  - Export co-located typed `@dataclass SandboxControlOption:` in `sandbox_toolbar.py`.

### 3. Canvas Widget & Iframe Boundary Integrity (`canvas_widget`)
- **Eliminate Preview Iframe DOM Penetration:**
  - Remove all code in [`canvas_widget.ts`](file:///home/marcel/projects/dj-design-system/dj_design_system/components/gallery/domain/canvas_widget/canvas_widget.ts#L126-L140) that inspects `iframe.contentDocument`, queries `.canvas-wrapper`, injects inline `<style>` tags with raw color literals, or mutates `dir='rtl'`.
  - Preview canvas styling (background, RTL, outlines, measurement) is communicated across the frame boundary via standard HTML query parameters (`?bg=...&dir=...`) or `postMessage` protocol, preventing cross-origin / cross-document DOM corruption.
- **Eliminate Sibling Event Sniffing & Storage Coupling:**
  - Remove document-level event listeners for `<dds-sandbox-toolbar>` events (`dds:sandbox-*`) from `canvas_widget.ts`.
  - Canvas properties (`zoom`, `viewport`, `bg`) are passed down as declarative HTML attributes or methods, coordinated by the parent template or gallery shell.
  - Remove `sessionStorage.getItem('dds_toolbar_state')` lookup.

### 4. Search Box Global Hotkey & Combobox A11y (`search_box`)
- **Decouple Document-Level Keydown Listener:**
  - Remove unconditional, un-scoped `document.addEventListener('keydown')` from [`search_box.ts`](file:///home/marcel/projects/dj-design-system/dj_design_system/components/gallery/domain/search_box/search_box.ts#L106-L120).
  - Support a declarative `data-global-shortcut="/"` attribute (or allow `<dds-gallery-shell>` to coordinate focus on `window.addEventListener('keydown')`), ensuring multi-instance previews don't suffer from focus hijacking.
- **WAI-ARIA Combobox Accessibility Implementation:**
  - Implement complete WAI-ARIA 1.2 Combobox pattern: generate unique `id`s for search result options and dynamically update `aria-activedescendant` on the `<input>` as arrow keys are pressed.
  - Automatically scroll active options into view within the scrollable dropdown container.
- **Typed `SearchIndexEntry` Dataclass:**
  - Export `@dataclasses.dataclass(frozen=True) class SearchIndexEntry:` (`id: str`, `title: str`, `url: str`, `category: str = "", tokens: str = ""`) in `search_box.py`.

### 5. HTMX & Client-Side Loop Harmonisation (`sandbox_params`)
- **Resolve Reactive Loop Contradiction:**
  - Harmonise client-side input debouncing: ensure `DDSSandboxParamsElement` does not trigger redundant, conflicting dispatch loops with HTMX form submission.
  - Make `dds:params-change` dispatch serialized parameter values for programmatic callers, while preserving clean HTMX swapping when HTMX attributes are present.
- **Remove Leaked Application Query Parameters:**
  - Remove hardcoded hidden inputs for `_iss`, `_dds_theme`, and `_dds_variant` from `sandbox_params.html`.
  - Provide a named `{% slot "extra_inputs" %}` slot (or attribute forwarding) so the host gallery page injects any routing-specific hidden inputs.
- **Remove Host DOM Selector Coupling:**
  - Remove hardcoded default `DEFAULT_HX_TARGET = "closest [data-gallery-sandbox-body]"`. Require `hx_target` to be passed explicitly by the consumer template or defaulted to a local ID.

### 6. Navigation Tree Data Contract & Semantic Structure (`nav_tree`)
- **Export Typed `NavTreeNode` Dataclass:**
  - Define and export `@dataclasses.dataclass(frozen=True) class NavTreeNode:` (`id: str`, `label: str`, `url: str = ""`, `icon: str = ""`, `children: Sequence[NavTreeNode] = ()`, `is_active: bool = False`, `is_expanded: bool = False`) from `nav_tree.py` and `__init__.py`.
  - Eliminate core dependency on internal gallery helper `NavItemInputData`.
- **Decouple Gallery Application Metadata:**
  - Remove gallery-specific properties (`active_variant`, `is_component`, `has_index_doc`) from the core tree node contract; map them at the view/template boundary.
